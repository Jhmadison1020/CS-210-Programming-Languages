# CS-210-Programming-Languages

# Summarize the project and what problem it was solving.
  The ChadaTech clock project was a time-tracking clock display program that allowed users to interact with it by updating hours, minutes, and seconds. It was created to display the traditional 12-hour clock format along with a military 24-hour clock format side by side while remaining synchronized. 

# What did you do particularly well?
  One thing I think I did particularly well was implementing a clean rollover with the time formats. As each time unit rolls over its maximum, it will call the add... functions to increment the next unit up. This means that once the seconds exceed 59, it will reset the seconds to 0 and increment the minute by calling the addMinute() function. 

# Where could you enhance your code? How would these improvements make your code more efficient, secure, and so on?
  At the time of this project, I didn't have all the knowledge or experience with C++ that I do now. One thing that could enhance the code I have built is additional fail-safes that protect the program from continuous loops. A prime example is within my printClockMenu() function. This function takes input from the user in the form of an integer that ranges from 1 to 4. This allows the user to make a selection of what they want to do with the application. Options are add hour, add minute, add second, and exit the program. Once the user makes a selection and inputs their decision, the program will call the associated function and will start incrementing the time on the clock app. There is a check to ensure that the selection is a number from 1 to 4, and if the number entered is out of this range, an error message will be displayed. The issue is that there is no check to ensure a number is entered. If the user were to enter a word or letter, there would be adverse effects. Using cin.fail() and cin.ignore() in these areas can boost the program's efficiency by clearing the input buffer and ignoring bad input, ultimately preventing an infinite loop. 

# Which pieces of the code did you find most challenging to write, and how did you overcome this? What tools or resources are you adding to your support network?
  The most challenging part of the code in this project was the alignment with the display of the clock display using only cout output statements. I overcame this issue by ensuring I knew each output could be replicated each time with the convertToTwoDigit() functions for the hours, minutes, and seconds. This made it easier because I knew the exact length of each clock display and could count out the spaces between the numbers while aligning the * symbols as the border around the clock for a clean display. One tool I more recently learned about and will be using in the future came from the C++ standard library <iomanip> section, where I found the setw() function that could be used to perfectly align the lines of code that displayed my clocks.

  This project was my first project where I learned to separate the code into a header file, implementation file, and main working file. I feel this will be transferable to many other projects in the future, and that is evident in the two projects within this course that I completed after this initial clock project. Both of the following projects in this class utilized the header, implementation, and main file formatting, which displays an understanding of how to write clean code. # How did you make this program maintainable, readable, and adaptable?
  I think I made this program maintainable, adaptable, and readable by creating clear header comments that show the owner, date created, and intent of the specific file. This was important because it informs future developers of when it was created, which can give the developer insight into the tools available to me at the time of creation. New information and tools may be developed as this industry continues to evolve, which would highlight my limitations. The intent section is important because it will describe what each file is meant to do and can allow a future developer the information needed to locate and pinpoint specific parts of the code to fix and update. On top of this, throughout the code, there are comments that describe functionality and the purpose of functions so a future programmer knows what was written and where. Utilizing multiple files to segment the program can allow future developers to extract my code and implement it in other formats. The implementation .cpp file can be moved from my simple display interface into other applications to be used again without necessarily rewriting the code to build the clock.
